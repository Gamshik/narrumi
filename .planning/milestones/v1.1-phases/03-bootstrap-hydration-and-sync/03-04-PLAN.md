# 03-04-PLAN: Settings no-flicker integration, rollback, and full verification

## Goal
Refactor the Settings screen to render its controls exclusively from the root bootstrap session, removing the local async fetch and the initial placeholder flicker. Surface explicitly mapped warning/error components for data recovery, offline, or sync failures.

## Requirements
- SET-01
- SET-02

## must_haves
- Settings MUST NOT use placeholder `initialPreferences`.
- Settings MUST read loaded preferences from `useBootstrapSession`.
- Settings MUST render `SettingsSkeleton` while the bootstrap session is hydrating.
- Settings MUST preserve its optimistic UI rollback logic when a save fails.
- If the bootstrap state has a recovered or sync-failed warning, `SettingsScreen` MUST display it as a `BubbleStatus` without blocking user edits.

## Artifacts this phase produces
- File `apps/mobile/src/presentation/app/bootstrap/settingsState.ts`
- File `apps/mobile/src/presentation/app/bootstrap/settingsState.test.ts`
- Refactored `SettingsScreen.tsx` without placeholder `useEffect` defaults.
