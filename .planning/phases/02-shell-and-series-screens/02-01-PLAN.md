<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User credentials -> AuthProvider | Email/password input is untrusted and must stay behind the existing auth hook/use-case boundary. |
| Auth/session errors -> UI status | Error values crossing into user-visible copy must stay safe and not expose sensitive SDK internals. |
| Status primitive -> screens | Shared display component must not infer app behavior or import services. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `AuthenticationScreen` status messages | medium | mitigate | Preserve current safe error handling and render user-facing status text through `BubbleStatus` without logging or displaying secrets. |
| T-02-02 | Elevation of Privilege | Auth presentation boundary | high | mitigate | Keep auth behavior behind `useAuthSession`; do not add Supabase SDK calls or session mutation logic to presentation components. |
| T-02-03 | Denial of Service | Disabled/loading submit controls | low | mitigate | Preserve disabled state while `isSubmitting` is true and expose accessible loading feedback near the submit action. |
| T-02-SC | Tampering | npm installs | low | accept | No package installs or dependency changes are planned. |
</threat_model>
