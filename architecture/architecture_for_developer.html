Архитектура Context-English MVP

Практичная Clean Architecture для React Native + Expo, Supabase и офлайн-первого прогресса. Это не структура папок, а карта ответственности, границ и потоков данных.

Главная идея

React Native Expo Managed Supabase Offline First

Приложение делится не по экранам, а по причинам изменения: интерфейс показывает состояние, application-слой выполняет сценарии, domain хранит правила MVP, infrastructure разговаривает с SDK и внешними сервисами.

Зависимости направлены внутрь: UI может знать use cases, use cases знают domain и порты, а конкретные SDK подключаются только снаружи через адаптеры.

Что это дает новичку в React Native

  • UI не превращается в место, где смешаны стили, бизнес-логика, Supabase и локальное хранилище.
  • Большинство решений можно тестировать без запуска телефона и без реальных сетевых вызовов.
  • Переход с AsyncStorage на SQLite или смена LLM провайдера не ломают сценарии приложения.
  • Офлайн-поведение становится архитектурным правилом, а не набором случайных проверок в компонентах.
Не добавляй абстракции ради абстракций. Порт нужен только там, где есть внешний источник данных, SDK, побочный эффект или правило, которое надо тестировать.

SOLID в этом проекте

S

Single Responsibility

Компонент рисует, use case выполняет сценарий, adapter работает с SDK, domain хранит правила.

O

Open/Closed

Новая реализация хранилища или AI провайдера подключается через порт без переписывания сценариев.

L

Liskov Substitution

Любой adapter обязан сохранять контракт: например, local progress write действительно завершается до sync.

I

Interface Segregation

Лучше маленькие порты для audio, grammar, story и storage, чем один большой сервис приложения.

D

Dependency Inversion

Use cases зависят от контрактов. Supabase, AsyncStorage и expo-speech зависят от этих контрактов как реализации.

M

MVP restraint

Чистая архитектура не означает тяжелую архитектуру: без Redux, CQRS, event bus и лишних слоев.

Что должно работать без интернета

  • Просмотр Oxford 5000 из bundle.
  • Карточная сессия с дневной целью.
  • Повторения и простая локальная практика.
  • Запись прогресса и completion state локально.
  • Очередь изменений для будущей синхронизации.

Что требует интернета

  • Генерация Text of the Day.
  • AI grammar helper.
  • Cloud sync с Supabase.
  • Любая операция, где нужен Edge Function или Auth.
При офлайне серверные действия не должны падать молча: экран показывает понятное состояние "доступно после подключения".

Правила, которые нельзя нарушать

  • Не вызывать OpenRouter или другой LLM provider из мобильного приложения.
  • Не добавлять native ios/ или android/ код: только Expo Managed Workflow.
  • Не загружать Oxford 5000 из сети во время работы приложения.
  • Не прятать бизнес-правила в компонентах React Native.
  • Не перезаписывать свежий локальный офлайн-прогресс старым remote state.
  • Не расширять MVP функциями из backlog без явного решения.
