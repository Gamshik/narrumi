Архитектура Context-English Series MVP

Clean Architecture для продукта, где главный объект - не карточка и не очередь повторений, а персональный AI-сериал: серии, эпизоды, Story Words, интерактив, память сюжета и мягкие learning signals.

Главная идея архитектуры

AI Series Story Words Offline First Expo Managed

Приложение делится по ответственности: интерфейс показывает состояние и принимает намерения пользователя, application слой выполняет сценарии, domain хранит правила продукта, infrastructure работает с SDK, локальным хранилищем, Supabase и Edge Functions.

Это архитектура, а не структура папок. Цель - понимать, где живут правила, какие зависимости допустимы и какие данные должны сохраняться локально до сети.

Правило зависимостей

  • Domain не знает про React Native, Supabase и AI SDK.
  • Application зависит от domain и портов.
  • Presentation вызывает use cases, но не хранит бизнес-правила.
  • Infrastructure реализует порты и знает конкретные SDK.
  • Edge Functions - отдельная backend AI boundary.
UI не должен напрямую читать Oxford JSON, писать в AsyncStorage, вызывать Supabase таблицы или дергать LLM.

Co-creation setup

Создание и редактирование сериала остается одним экраном с progressive disclosure, а не wizard. Level, Genre, Tone, Participation Mode и необязательное Your idea видны сразу. По желанию раскрываются worldAndSetting, backstory, storyDriver, preferredCastSize (1–4 или выбор AI), mustInclude и avoid; существующие профили персонажей остаются редактируемыми.

User anchors exactly preserved
Draft strategy fill gaps / refine / rebuild
Contextual AI action online-only, strategy-enforced
Edit suggestions edited AI field becomes user-authored
Local first brief + provenance + sync
Fill gaps не меняет заполненные поля; Refine выборочно перерабатывает только полезные кандидаты; Rebuild исключает старый итоговый черновик из model context. Пустые видимые карточки персонажей передаются как отдельные AI-fill slots, а AI choice может дополнить уже начатый состав. Числовой preferredCastSize точен для Refine и Rebuild; Fill gaps не сокращает готовый состав и показывает это ограничение в UI. Для старых записей стратегия безопасно становится fill-missing, а существующие setup-поля без provenance считаются пользовательскими.
Форму и локальный черновик можно использовать офлайн; без сети отключается только AI-достраивание. После первого эпизода весь setup становится read-only.
Safety и copyright moderation могут отказать в генерации или предложить оригинальную альтернативу, но не должны удалять или переписывать сохраненный локально пользовательский текст.

Основные доменные сущности

Series

Контейнер истории: название, жанр, уровень, тон, premise, персонажи или роль пользователя, compact memory, creative brief, setup provenance и sync metadata.

Creative Brief

Необязательные пользовательские опоры, draftStrategy и происхождение каждого генерируемого setup-поля. Нужен для совместного придумывания без потери авторства.

Episode

Короткая учебная серия: recap, сцена или диалог, Story Words, interaction point, feedback, cliffhanger и summary update.

Word Set

Today's Words, Episode Words или Series Words. Это простой выбор слов для сюжета, не очередь повторений.

Series Memory

Компактная память: конфликт, факты, открытые вопросы, объекты, локации, last summary, cliffhanger и recurring words.

Learning Signal

Непунитивные события: encountered, selected, translated, used, corrected, resurfaced, stable. Они влияют на подсказки.

Story Words

Story Words - это легкий выбор слов для будущего эпизода, а не полноценный словарный тренажер. Он собирает предложения из Oxford 5000, уровня пользователя, жанра, памяти серии и learning signals.

Use in episode Know it Later Remove
Если пользователь выбирает много новых слов, приложение предупреждает о сложности, но не блокирует выбор жестким лимитом.

No Review Debt

В MVP нельзя возвращать старую модель с обязательными SRS-очередями. Пропущенные дни не создают долг. Встреченные слова могут возвращаться естественно, когда подходят сюжету, уровню и выбранному word set.

Запрещено делать flashcard-first поток, scheduled due reviews и punitive backlog основой MVP.

AI boundary

Mobile App JWT + typed request
Edge Function validation, secrets, bounded context
Episode Writer Gemini 3.5 Flash-Lite: story prose
Reviewer GPT Mini: workflow rules + evidence
Episode JSON client validates again

Мобильное приложение не хранит LLM ключи, prompts, provider settings или model choices. Оно отправляет компактный контекст и получает структурированный результат. Для setup Edge Function валидирует provenance и возвращает изменения только для пустых или AI-полей; safety и copyright moderation остаются серверными. Learner feedback и compact memory создаются отдельно от creative continuation. Сначала Gemini Writer создает story prose, затем GPT-5.4 Nano Decision Builder строит prompt и choices только из замороженного текста. Отклоненный полный draft получает одну точечную правку stronger model по issue code, evidence и repair instruction; структурно сорванный writer допускает один полный fallback. Результат снова проходит тот же reviewer, и любое оставшееся semantic violation блокирует сохранение. Дешевый GPT Nano используется отдельно для learner feedback и compact memory. Utility сначала создает только английские semantic reader blocks, затем сервер находит Story Word targets, и отдельный запрос переводит только эти targets на русский. Связанные предложения остаются одним смысловым блоком, реальные реплики отделяются с pinned speaker metadata, а Cyrillic запрещен во всех learner-facing полях кроме translation values.

Работает без интернета

  • Список уже созданных серий.
  • Чтение уже сгенерированных эпизодов.
  • TTS по смысловым блокам для сохраненных эпизодов.
  • Oxford 5000 browsing/search.
  • Story Words из локальных данных.
  • Локальные word sets, signals и preferences.
  • Локальные изменения, не требующие AI.
  • Заполнение и сохранение локального setup draft.

Требует интернета

  • Генерация нового эпизода.
  • AI strategy action для series setup.
  • AI continuation после выбора или reply.
  • AI correction и grammar-style explanation.
  • Cloud sync с Supabase.
Для server-only действий UI показывает явный offline state: "будет доступно после подключения".

SOLID в этой архитектуре

S

Single Responsibility

UI рисует, use case выполняет сценарий, domain защищает правила, adapter работает с SDK.

O

Open/Closed

Новые правила подсказок Story Words или другое хранилище добавляются через порты.

L

Liskov Substitution

Любой adapter сохраняет контракт: local write завершается до sync.

I

Interface Segregation

Отдельные маленькие порты для episode generation, interaction, audio, storage и sync.

D

Dependency Inversion

Use cases зависят от контрактов, а Supabase, AsyncStorage и expo-speech их реализуют.

M

MVP restraint

Без Redux, CQRS, event bus и лишних слоев, пока MVP не докажет необходимость.

Нельзя нарушать

  • Не делать flashcards или SRS главным потоком MVP.
  • Не показывать due reviews, review debt или missed-day backlog.
  • Не вызывать OpenRouter или другой LLM provider из мобильного приложения.
  • Не хранить prompts, model choices или AI secrets во frontend.
  • Не отправлять в LLM всю историю сериала без ограничений.
  • Не копировать copyrighted worlds, characters, names или plots.
  • Не загружать Oxford 5000 из сети во время работы приложения.
  • Не добавлять native ios/ или android/ code.
  • Не прятать sync, AI validation или правила Story Words в UI.
  • Не перезаписывать свежие локальные записи старым remote state.
  • Не перезаписывать user-authored setup поля генерацией.
  • Не добавлять направление для следующего эпизода: co-creation этой итерации относится только к initial series setup.
