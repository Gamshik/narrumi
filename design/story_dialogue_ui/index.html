# GOAL: Implement Dialogue & Narrative styles in EpisodeReaderScreen with Top-Fixed Player

We want to enhance the UI/UX of the story reader in `apps/mobile` by automatically rendering character dialogues inside speech bubble blocks, formatting narrative as indented paragraphs, and placing the audio player statically at the top of the screen (below the header) to prevent text overlap.

### 1. Layout Architecture (UX Overlap Protection)
- Restructure the screen layout using a vertical Flex column inside a SafeAreaView.
- Top Section (Fixed): Sleek top dock containing the Screen Title and the compact AudioControls card.
- Middle Section (ScrollView - flex: 1): The story reader text scrolls inside this area, flowing cleanly under the top player.
- Bottom Section (Fixed): The navigation tab bar.
- Result: Reader text is physically separated from controls and never overlaps under any text length, scrolling, or screen orientation.

### 2. Dialogue & Narrative Formatting
- Dialogue Block:
  - Flex Row layout with an Avatar circle on the left (`width: 32px`, initials centered).
  - Right content: A small speaker name label, and a speech bubble with a translucent background colored by speaker accent.
  - Bubble width stretches up to 86% of container width (no excessive empty space).
  - Narrative carrier clause (e.g. "asked Lily") is rendered below the bubble in small italic.
- Narrative Block:
  - Rendered as standard text block with `margin-left: 40px` (aligned with the bubble text to prevent eye jumping).
- Vocabulary highlights:
  - Ensure inline tap-to-translate annotations still work inside the speech bubble chunks! Text must be mapped to `buildSentenceTextChunks`.

### 3. Integration with TTS & Focus Dimming
- During TTS playback, keep the active block (whether narrative block or speech bubble) at `opacity: 1`.
- Dim inactive blocks to `opacity: 0.45`.
- Make sure tapping any word inside a dialogue box opens the translation sheet.
